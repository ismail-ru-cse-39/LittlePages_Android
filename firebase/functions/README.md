# Trusted backend source

`index.mjs` defines authenticated, App Check protected callable operations for configuration drafts (`saveConfigurationDraft`, `validateConfigurationDraft`, `getConfigurationDraftPreview`, `approveConfigurationDraft`, `publishConfigurationDraft`, and `rollbackConfigurationPublication`) and private discount-code campaigns (`createDiscountCodes`, approval/publish/pause/archive, and `reserveDiscountedOrder`). Configuration drafts use optimistic draft and publication revisions. Publishing validates the full configuration/product/promotion snapshot, writes immutable numeric configuration/catalogue revisions and audit records in one Firestore transaction, then advances `publicConfiguration/current`. Rollback verifies the target snapshot hash and metadata before advancing the manifest as a new publication revision. Product and promotion writes are bounded to 300 and 100 records, respectively, to keep transactions under Firestore's write limit.

Role capabilities are enforced from trusted `adminRoles/{uid}` records: `catalog_editor` can edit/validate and create code drafts, `publisher` can edit/validate/publish/rollback and publish codes, and `administrator` can additionally approve configuration/code campaigns and manage staff through `setStaffRole`. Code campaign creation validates product/category targets against the current pinned published catalogue inside the same transaction that creates private code records; redemption rechecks targeted categories against the current published configuration. The role callable verifies the target Auth account, writes the role/status with an audit event, and prevents demoting or disabling the last active administrator. A first administrator still must be provisioned through a trusted owner bootstrap before the callable can be used. Clients must never write role, draft, approval, publication, or audit records directly. App Check must be enforced and roles provisioned only by an owner-controlled process.

`discount-domain.mjs` contains dependency-free validation and pricing primitives. The private code collection stores only HMAC digests; plaintext codes are returned once by the authenticated creation call. Configure the `LITTLEPAGES_DISCOUNT_HMAC_KEY` secret with a securely generated random value of at least 32 characters before invoking either code operation. The Firebase project must have App Check enforcement configured for callable functions, and active staff records must be provisioned only by a trusted owner process at `adminRoles/{uid}`.

`publishing-domain.mjs` provides canonical JSON hashing, schema/reference/business-policy validation, publication review blockers, minimum-client-version validation, and write bounds. A publication includes only `published` products and `active` or `scheduled` promotions; draft, archived, and paused records stay out of public collections. The public content hash covers `{schemaVersion, configuration, products, promotions}` with products/promotions sorted by stable ID; it excludes manifest metadata. `firebase.json` points the Firebase CLI at these Functions and the repository's deny-by-default Firestore and Storage rules. Source has not been installed, emulator-verified, deployed, or connected to the user's Firebase project. The configured function region is `asia-south1`; verify it matches the existing Firestore database location before deployment. The browser admin does not yet invoke these callables.
